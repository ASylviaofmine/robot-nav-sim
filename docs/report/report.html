Grid Planning and Feedback Control Implemented from Scratch

Code: github.com/ASylviaofmine/robot-nav-sim

Abstract. This report describes a navigation stack for a planar mobile robot, written from scratch in Python with no robotics framework. A grid map is searched with A* under a Manhattan heuristic, and the resulting waypoints are followed by a proportional go-to-goal controller. Rather than asserting that the system works, every claim is measured: the planner is cross-checked against breadth-first search on five hand-built maps (identical path lengths in 16 of 16 cases), the effect of the heuristic is quantified (130 versus 250 node expansions on the same problem), and tracking accuracy is reported as cross-track error (0.090 m maximum, 0.013 m mean) alongside a sensitivity sweep over three controller parameters. Two failure modes encountered during development — heading wrap-around and waypoint skipping — are documented with their measured consequences.

1. Introduction

Given a map with obstacles, a start pose and a goal pose, a mobile robot must produce a collision-free route and then execute it. The problem decomposes into planning (a discrete search over the map) and control (a continuous feedback law that keeps the robot on the planned route). This project implements both, plus the visualization needed to inspect what happened. The constraint that shaped every decision was to avoid a robotics framework: a framework would have produced a working demo but no understanding, and it would have hidden the two failure modes reported in §4.3 — exactly the kind of defect that writing the loop by hand exposes.

2. System architecture

The code is organized as five modules with strictly one-way dependencies: grid (map representation and cell/world coordinate conversion) → planner (A*) → simulation (assembles one complete run) → viewer (Pygame window and GIF export). controller depends on nothing but NumPy: it accepts a list of waypoints and never imports the map, so replacing the planner with a sampling-based method would not touch it. A single entry point, python main.py, wires the modules together.

3. Methods

3.1 Planning: A* on a four-connected grid

A* expands nodes in order of f(n) = g(n) + h(n), where g is the cost already paid and h estimates the remaining cost. With unit step costs and a Manhattan heuristic h = |Δr| + |Δc|, h never overestimates the true remaining steps — it is admissible — so the first time the goal is expanded, the path is optimal. The search is O(N log N) in the number of cells for the heap operations. Out-of-bounds neighbours are treated as walls, which removes boundary checks from the inner loop.

3.2 Control: proportional go-to-goal with heading wrapping

At each step the controller computes the bearing to the current waypoint, θ* = atan2(Δy, Δx), the heading error e = θ* − θ, and applies θ ← θ + Kp e Δt before advancing along the new heading. The error is first wrapped into (−π, π]. Without wrapping, the accumulated heading grows without bound and the correction saturates; the robot circles a waypoint indefinitely (measured: 100 m travelled, 4 of 17 waypoints reached). A waypoint is considered reached when the distance falls below a tolerance tol, at which point the index advances by exactly one.

Tracking accuracy. The closed loop reaches the goal in 32.00 s, travelling 16.00 m against a planned 16.00 m, with an end-point error of 0.039 m. Cross-track error, measured as the distance from each trajectory sample to the planned polyline, peaks at 0.090 m and averages 0.013 m; the largest deviations occur at the two 90° corners, where the robot cuts the turn.

Table 3 contains a result worth separating from the usual accuracy/speed trade-off. Between tol = 0.02 and 0.15 the maximum cross-track error does not move at all — it stays at 0.0895 m — while the end-point error grows by a factor of ten. The peak lateral deviation is therefore fixed by the corner geometry, not by the tolerance: the controller cuts each 90° turn by roughly the same amount however early it accepts a waypoint. What tol actually changes is how soon the robot turns towards the next waypoint, and that shows up as distance saved (16.13 → 15.50 m) rather than as lateral drift. Reading the two error columns together is what makes this visible; either one alone would have suggested a simple trade-off.

5. Limitations

  • Discrete planning. A four-connected grid produces 90° corners and one-cell clearance; the robot footprint is ignored, so trajectories are not physically smooth.
  • No replanning, ideal state estimation. The controller follows the route it was given and cannot detect obstacles that appear afterwards; pose is assumed known exactly, with no noise or sensor model.
  • Correctness depends on the tracker. The path is certified collision-free only if the waypoint index advances one at a time. Advancing by two cuts a corner and enters the wall — measured, not hypothesised.
  • Single machine, single map family. Runtimes come from one laptop; weighted terrain, larger maps and diagonal motion are untested.

6. Conclusion

A planner, a controller and a viewer, each written by hand and each measured, form a closed navigation loop whose behaviour is understood end to end. The measurements show that a Manhattan heuristic halves the search on the tested maps without sacrificing optimality, that proportional heading control tracks the planned route to within nine centimetres, and that both defects found along the way were invisible until the numbers were inspected. Natural next steps: a sampling-based planner on identical maps, and a true differential-drive model with wheel-level commands.
